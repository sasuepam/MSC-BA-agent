Feature Summary

Business Context

MSC Cruises handles a significant volume of group bookings via Travel Agencies (TAs) across multiple inbound channels: phone (via IVR), email, and the MSC Book B2B web portal. Two gaps exist in the current state for DTP rolled-out markets:

  1. Group ID not captured on Salesforce Case from webforms: When a Travel Agency submits a Help Center, Need Help, or Group Request form via MSC Book, the Group ID — the identifier that uniquely identifies a group reservation — is not automatically included in the case created in Salesforce. Contact centre agents must manually look up the Group ID, adding effort and introducing risk of error.
  2. Group booking type not available in Booking Events: Booking events published to downstream consumers do not carry information about whether a booking is a group or individual booking, so systems such as CDP (Adobe Customer Data Platform) cannot distinguish between the two for segmentation and marketing purposes.

What this feature delivers

  • Stream 1 – Group ID on Webform Case (MSC Book → Salesforce): When a Travel Agency submits a Help Center, Need Help, or Group Request form via MSC Book, the Group ID entered on the form is automatically carried through to the Salesforce Case so that contact centre agents have immediate visibility without a manual lookup. The Group ID is also displayed and editable directly in the Case record. Additionally, where the Group ID was not provided at form submission, it will be automatically populated on the Case when the related booking is linked. This applies to DTP rolled-out markets only; non-DTP markets continue on the existing path unchanged.
  • Stream 2 – Group booking type in Booking Events (DTS → CDP): Booking events are extended to include information about whether a booking is a group or individual booking. This allows downstream consumers such as CDP to correctly identify and segment group bookings for marketing activation. The change is additive and does not impact existing consumers.

DTP Market Rollout (MuleSoft path active): Ireland, UK, DACH, MED+Latam (May 2026), US (Sep 2026).

Non-DTP Markets: Remain on existing CRM AS-IS / Siebel integration — no change in scope for this feature.

Business Requirements

IDRequirementsDescription
BR-001 As a Travel Agency Group User, I want the Group ID I enter on the MSC Book webform to be automatically stored on the Salesforce Case so that contact centre agents can immediately identify the group booking without a manual DTS lookup. When a TA submits a Help Center, Need Help, or Group Request form on MSC Book for a DTP rolled-out market, the optional groupId field entered by the user must be included in the payload sent to MuleSoft INT101 and stored in groupId__c (Text 255) on the Salesforce Case. If not provided, the field remains null on the Case.
BR-002 As a Marketing Automation user, I want the group booking type to be included in booking events so that I can identify and segment group bookings differently from individual bookings for marketing activation. Booking events must be extended to carry the group booking type. The field must be populated for group bookings only and absent or null for individual bookings. MuleSoft must forward this value to CDP in all relevant booking event flows. The change must be backward-compatible so existing consumers are not affected.

Use Cases

UC#PreConditionActor/sUse CaseFunctionality ExpectedOpen Questions
UC-001
  • Travel Agency user is logged in to MSC Book (Help Center — authenticated form).
  • The market/country is a DTP rolled-out market (Ireland, UK, DACH, MED+Latam or US).
 Travel Agency User (authenticated on MSC Book B2B portal) Create Salesforce Case from Help Center Webform (DTP Market) with Group ID
  1. User completes the MSC Book Help Center form, optionally entering a Group ID in the dedicated groupId field.
  2. MSC Book sends the form payload, including groupId if provided, to MuleSoft INT101.
  3. MuleSoft INT101 forwards the request to Salesforce, passing through the groupId value.
  4. Salesforce creates the Case record with groupId__c populated from the submitted value (if present), and links to the agency and customer where identified. Even if the agency or customer is not found, the Case is still created.
  5. Salesforce asynchronously routes the Case to Genesys for queue assignment.
  6. MuleSoft returns the caseId confirmation to MSC Book.
  7. MSC Book displays a confirmation to the user.
  • Group ID field accepts Text(255). The field is optional and no transformation is applied by MuleSoft — the value is passed through as submitted.
  • Salesforce Origin field value for INT101 — already in place.
  • webformCode__c value for the Help Center form type — already in place.
UC-002
  • DTS publishes a Booking Event for a group booking (GRP) including the GroupType field.
 DTS, MuleSoft INT024.1 / INT100 / INT025, CDP Forward GroupType in Booking Events to CDP for Group Bookings
  1. DTS publishes a booking event for a group booking containing the GroupType field.
  2. MuleSoft INT024.1, INT100, and INT025 each receive the event and include GroupType in the payload forwarded to CDP.
  3. CDP receives the booking event with GroupType populated and processes the group booking accordingly.

  • GroupType data type: String.
