Feature Summary

MSC Cruises uses Attentive as its marketing communications platform for email and SMS channels. Customer opt-in and opt-out preferences are captured in Attentive in real time when customers subscribe or unsubscribe from marketing communications. This feature delivers two new MuleSoft webhook integrations — INT172 (Attentive Webhook Subscription) and INT174 (Attentive Webhook Unsubscription) — to ensure that these consent preference changes are propagated in real time to the MSC Customer Hub (CHUB) and the Customer Data Platform (CDP), so that customer preferences are consistent across all MSC systems without delay.

INT172 handles subscription events (event types: email.subscribed, sms.subscribed) and INT174 handles unsubscription events (event types: email.unsubscribed, sms.unsubscribed). Both integrations follow the same orchestration pattern: validate the HMAC-SHA256 signature on the inbound Attentive request, upsert the customer in CHUB via CH042 using the email address as the key identifier, import the updated profile to CDP via A092, and send tracking history for the event to CDP via A094. MuleSoft returns 200 OK to Attentive only after all downstream calls complete successfully. Any downstream failure causes an error response to be returned to Attentive, which applies an exponential backoff retry strategy for up to three days.

The Attentive webhook payload format is fixed and cannot be customised; requests must conform to the default Attentive subscription or unsubscription event schema. Each interface (INT172 and INT174) uses a separate, environment-specific HMAC-SHA256 signing key. Security is enforced at three layers: HMAC-SHA256 signature validation using the x-attentive-hmac-sha256 header, client credentials enforcement (static clientId and clientSecret passed as query parameters), and IP whitelisting of Attentive source addresses on Akamai under the verified-legacy category. All downstream integrations (CH042, A092, A094) must be idempotent to prevent duplicate records when Attentive retries events.

Requirement ID Interface Requirement Description Category Priority
NFR-001 INT172, INT174 Both INT172 and INT174 must validate the HMAC-SHA256 signature on every inbound request before executing any downstream call. The digest is computed from the raw request body and compared against the x-attentive-hmac-sha256 header value using the environment- and application-specific signing key. Requests with an invalid or missing signature must be rejected immediately with an error response. No downstream calls may be made for requests that fail signature validation. Security High
NFR-002 INT172, INT174 INT172 and INT174 must each use a separate, environment-specific HMAC-SHA256 signing key. INT172 uses a different signing key from INT174, reflecting that they are separate Attentive webhook applications per environment. Security High
NFR-003 INT172, INT174 Client credentials (static clientId and clientSecret) passed by Attentive as query parameters must be validated via the client enforcement policy on INT172 and INT174 respectively. Each interface has its own set of client credentials. Security High
NFR-004 INT172, INT174 Attentive source IP addresses must be whitelisted on Akamai under the verified-legacy category. Requests originating from non-whitelisted IPs must be blocked at the Akamai layer before reaching the MuleSoft endpoints. Security High
NFR-005 INT172, INT174 INT172 and INT174 must return 200 OK to Attentive only after all downstream calls (CH042, A092, A094) have completed successfully. Any downstream failure must result in a non-2xx error response to Attentive, enabling Attentive's exponential backoff retry strategy to activate. Availability High
NFR-006 CH042, A092, A094 All downstream integrations invoked by INT172 and INT174 (CH042, A092, A094) must support idempotent processing. Attentive may retry a webhook event for up to 3 days using an exponential backoff strategy. Repeated processing of the same event must not result in duplicate customer records in CHUB or CDP. Availability High
NFR-007 INT172, INT174 INT172 and INT174 must accept and process webhook payloads in the default Attentive subscription and unsubscription event schemas respectively. The Attentive payload format is fixed and cannot be customised. The email address is always present; the phone number may be absent for email event types. Compliance High
