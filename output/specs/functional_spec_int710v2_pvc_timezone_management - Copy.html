Feature Summary

US regulations require that call centre agents may only contact customers within permitted hours in the customer's own time zone (9:00 AM to 9:00 PM). Previously, this restriction was enforced for customers routed through campaign queues but was not applied to customers being routed directly to their assigned Personal Vacation Consultant (PVC). As PVC assignment has gone live in the US market, any customer with an assigned PVC must now also have their callback scheduled to respect these time zone restrictions.

This feature extends the campaign contact creation flow with two additions. First, before creating a case or scheduling a callback, the integration now determines the earliest time at which the customer may legally be contacted. The customer's time zone is derived from the area code of their phone number (for US and Canada) or from the country code of their phone number (for all other countries). If the phone number does not include a country code prefix, the customer's country of residence is used to derive it. A dedicated utility service calculates the earliest contactable date and time in the customer's time zone, using a configured schedule of socially acceptable calling hours per time zone. Any failure in this step halts the entire flow and returns an error; no case or callback is created in that event.

Second, the response from the case creation step now indicates whether the customer has a PVC assigned. If the customer has no PVC, the existing behaviour is followed: the customer is added to a campaign contact list, with the addition of their resolved time zone so that Genesys can enforce the contactable hours window when assigning the lead to an agent. If the customer does have a PVC, a direct callback is scheduled in the PVC's personal callback queue at the calculated earliest contactable time, ensuring the PVC agent is not presented with the lead before the customer can legally be called. After a successful callback is scheduled, the associated case is updated asynchronously with the Genesys interaction identifier.

BR-001 As a contact centre manager, I want customers to be added to the campaign contact list or PVC callback queue with their resolved time zone included so that Genesys can apply the contactable hours window when assigning leads to agents. The customer's time zone must be resolved from the area code of their phone number (US/Canada) or the country code of their phone number (all other countries), with a fallback to the customer's country of residence if no country code prefix is present. The resolved time zone must be included when adding the customer to the campaign contact list (no PVC) or when scheduling the callback in the PVC's personal callback queue (PVC assigned), so that Genesys enforces the contactable hours window in either path.

INT710 calls Salesforce S008.2V2 to check for existing relevant cases. No case is found, so processing continues.

INT710 calls the Azure Function AZF003 with the phone number and market code to retrieve the customer's resolved time zone and earliest contactable date and time. AZF003 returns the time zone (IANA format) and the contactable date and time (UTC with offset).

INT710 calls Salesforce S008V3 to create a case. The response includes a flag indicating whether the customer has a PVC assigned.

Happy path – no PVC assigned: INT710 calls Genesys GEN070 to add the customer to the campaign contact list, including the resolved time zone in the contact entry. INT710 returns a successful response to AJO. Asynchronously, INT710 calls Salesforce S202 to update the case with the Genesys contact identifier; errors in this step are not returned to AJO.

Happy path – PVC assigned: INT710 calls Genesys GEN001 to schedule a direct CTI callback in the PVC's personal callback queue at the contactable date and time returned by AZF003. INT710 returns a successful response to AJO. Asynchronously, INT710 calls Salesforce S202 to update the case with the Genesys callback identifier; errors in this step are not returned to AJO.

Alternative path – AZF003 error: If AZF003 returns an error (invalid phone number, market code not recognised, market code recognised but cannot be resolved to a country, no contactable hours configured for the resolved country, or no default country row in the configuration), INT710 terminates immediately and returns an error to AJO. NFR-001 INT710 / AZF003 The call to AZF003 is a new synchronous step added to the INT710 orchestration. Its response time must not cause the overall INT710 request to exceed the existing agreed SLA for this integration. The expected response time for AZF003 must be confirmed and validated against the INT710 SLA budget. Performance High
NFR-002 INT710 / AZF003 Any error returned by AZF003 — including invalid phone number, unrecognised market code, missing contactable hours configuration, and missing default country configuration — must cause INT710 to terminate immediately and return an error to AJO. No Salesforce case and no Genesys contact or callback must be created when AZF003 has not successfully returned a contactable slot. This prevents orphaned cases in Salesforce. Error Handling High
NFR-003 INT710 / AZF003 The socially acceptable contactable hours configuration used by AZF003 (stored in Azure Storage Account) must be maintainable without a code deployment. Changes to calling hours per country or time zone must take effect by updating the configuration file only. Maintainability Medium
NFR-004 INT710 / S202 The Salesforce case update with the Genesys interaction identifier (S202) must be performed asynchronously and must not block or delay the successful response returned to AJO. Errors in the S202 call must be logged for operational visibility but must not be propagated to AJO or cause a retry of the full INT710 flow. Error Handling High
NFR-005 INT710 / AZF003 AZF003 must be able to handle concurrent requests from INT710 without degradation, given that AJO may trigger multiple campaign contact creation requests in parallel. The Azure Function must be configured for appropriate scaling to handle peak campaign volumes. Scalability Medium
NFR-006 INT710 The contactable date and time returned by AZF003 and passed to GEN001 for PVC callback scheduling must be stored and transmitted in UTC with offset (e.g. 2026-07-28T09:00:00.000-05:00). The time zone string passed to GEN070 must be in IANA format (e.g. America/New_York). Both formats must be validated before forwarding to Genesys. Compliance High
