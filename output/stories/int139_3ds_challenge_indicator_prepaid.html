CR: INT-139 — 3DS Challenge Indicator for Prepaid Flow

Interface: INT-139 | Initiative: Datatrans 3DS Secure Fields | Status: Draft

Summary

Introduce the threeDSRequestorChallengeInd parameter in the Datatrans init API call for the prepaid payment flow, setting it to 02 (frictionless preferred, no challenge requested) to reduce the elevated decline rate on prepaid transactions caused by unnecessary 3DS challenges.

Change Scope

  • Add threeDSRequestorChallengeInd = "02" to the Datatrans init API request for prepaid flows only.
  • All other flows (booking funnel, MyMSC booking payments) must not send this parameter — Datatrans Secure Fields will continue to default to 04 for those flows.
  • No change required to the Secure Fields integration itself for non-prepaid flows (default behaviour is already 04).

Interfaces Affected

  • INT-139 — Datatrans Secure Fields (Prepaid Flow) (DTP / Datatrans)
    Add threeDSRequestorChallengeInd = "02" in the Datatrans init API call when the transaction is identified as a prepaid payment. Parameter must be omitted for all non-prepaid flows.

Rationale

  • Prepaid transactions are experiencing a high decline rate due to the Secure Fields integration triggering 3DS challenges at an elevated rate.
  • Datatrans have proposed setting threeDSRequestorChallengeInd = "02" (frictionless preferred) for prepaid flows to reduce unnecessary challenge prompts and lower the decline rate.
  • Scope is limited to the DTP project — 3DS Secure Fields is used exclusively for prepaid in this context.

Resources & Dependencies

  • Datatrans init API documentation — Datatrans — Reference for threeDSRequestorChallengeInd parameter values and behaviour
  • Prepaid flow detection logic — DTP MuleSoft team — Confirm how the integration layer identifies a prepaid transaction to conditionally set the parameter [TO BE CONFIRMED]

Acceptance Criteria

GIVEN a customer initiates a prepaid payment through the DTP project
WHEN the Datatrans init API call is made
THEN the request includes threeDSRequestorChallengeInd = "02"

GIVEN a customer initiates a booking funnel payment
WHEN the Datatrans init API call is made
THEN the request does NOT include the threeDSRequestorChallengeInd parameter, and Datatrans defaults to 04

GIVEN a customer initiates a MyMSC booking payment
WHEN the Datatrans init API call is made
THEN the request does NOT include the threeDSRequestorChallengeInd parameter, and Datatrans defaults to 04

GIVEN the change is deployed to production
WHEN prepaid transactions are processed over a representative period
THEN the prepaid decline rate is measurably reduced compared to the pre-change baseline [threshold to be confirmed with Datatrans / business]
