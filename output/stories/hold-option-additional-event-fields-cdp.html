BA Stories — Hold Option Additional Event Fields in CDP

Initiative: Hold Option Additional Event Fields in CDP | Jira Reference: CRM2-11036 | Generated: 12/Aug/2026

CR: Enrich Hold Option CDP Event with Additional Fields (INT-006)

Interface: INT-006 | Initiative: Hold Option Additional Event Fields in CDP | Status: Draft

Summary

The Hold Option CDP event fired by the INT-006 MuleSoft integration currently contains insufficient data for downstream CRM and Cheetah email templates to render personalised content. This change enriches the event payload with four additional fields — ship code, cabin category code, itinerary description, and cruise length — so that customer-facing Hold Option email templates can display meaningful, context-specific cruise information.

Change Scope

  • The Hold Option CDP event is dispatched via the A070 downstream request within INT-006. This change enriches the A070 payload with four additional optional fields — all four fields are defined as optional in the CDP payload so that the event is not blocked or failed if the DTS Itinerary Details API call is unavailable or incomplete.
  • Add shipCode (optional) to the Hold Option CDP event payload. Derived from the first two characters of the Cruise ID already available in the INT-006 request. No new data source required.
  • Add cabinCategoryCode (optional) to the Hold Option CDP event payload. Sourced from the booking funnel payload already processed by INT-006. One or more codes are concatenated as a comma-separated string consistent with the abandoned cart integration pattern.
  • Add itineraryDescription (optional) to the Hold Option CDP event payload. Sourced from the DTS Itinerary Details API response, which is already called non-blocking at the start of the INT-006 flow. If the DTS call fails, this field is absent or null and the event is still fired.
  • Add cruiseLength (optional, number of nights) to the Hold Option CDP event payload. Sourced from the DTS Itinerary Details API response. As with itinerary description, if the DTS call fails, this field is absent or null and the event is still fired.
  • The DTS Itinerary Details API call within INT-006 must remain non-blocking. No new synchronous external API calls are introduced by this change.
  • When the DTS call fails, INT-006 must log the failure (error type, Cruise ID, timestamp) and continue — the hold option creation and CDP event dispatch must not be blocked.
  • Full ship name (localised) is explicitly out of scope for this change — it is not returned by the POST booking response and would require a DTS dependency; noted as an open item.
  • Full port list is explicitly out of scope for this iteration.
  • Business logic for mapping ship code to full ship name, and any localisation of field values for email templates, is handled downstream by CDP/Cheetah and is out of scope for MuleSoft.

Interfaces Affected

  • INT-006 — Hold Option API (MuleSoft / B2C Website / CDP)
    The MuleSoft INT-006 Hold Option integration is updated to populate four additional optional fields (shipCode, cabinCategoryCode, itineraryDescription, cruiseLength) in the CDP event payload it fires upon a successful hold option creation.
  • A070 — CDP Event Request (downstream / CDP)
    A070 is the downstream request from INT-006 to CDP that delivers the Hold Option event. The A070 payload is extended to include the four new optional fields.

Rationale

  • The current Hold Option CDP event lacks sufficient data for Cheetah email templates to render personalised content (ship name reference, cabin type, itinerary summary, cruise duration).
  • CRM and Marketing teams require these fields to produce customer-facing Hold Option emails that include meaningful cruise details.
  • All four required fields are available from data sources already in the INT-006 flow, minimising the cost and risk of this change.
  • The Cheetah formula logic for conditionally displaying content based on cruise length (e.g. short-haul vs. long-haul messaging) depends on the cruiseLength field being present in the CDP event.

Acceptance Criteria

GIVEN a valid Hold Option creation request is received by INT-006 with a Cruise ID of two or more characters, and the DTS Itinerary Details API returns a successful response
WHEN a POST request is made to the INT-006 Hold Option API endpoint
THEN the API returns HTTP 200 (or 201 — [TO BE CONFIRMED]) and the CDP event payload contains all four additional fields: shipCode (first two characters of the Cruise ID), cabinCategoryCode (category code from the booking funnel payload), itineraryDescription (description string from DTS), and cruiseLength (integer number of nights from DTS) — all populated and not null.

GIVEN a valid Hold Option creation request is received by INT-006, and the DTS Itinerary Details API is unavailable or returns a timeout or error response
WHEN a POST request is made to the INT-006 Hold Option API endpoint
THEN the API still returns HTTP 200 (or 201), the hold option is created, and the CDP event is fired with shipCode and cabinCategoryCode populated; itineraryDescription and cruiseLength are absent or null. A failure entry is written to the MuleSoft application log including error type, Cruise ID, and timestamp.

GIVEN a valid Hold Option creation request is received by INT-006, and the DTS Itinerary Details API returns a response that omits the itineraryDescription or cruiseLength fields
WHEN INT-006 processes the DTS response
THEN the missing fields are set to null or absent in the CDP event payload — not populated with default or invented values. The hold option is created and the CDP event is fired without an unhandled exception.

GIVEN a Hold Option creation request containing one or more cabin category codes and the DTS Itinerary Details API returns a successful response
WHEN a POST request is made to the INT-006 Hold Option API endpoint
THEN the cabinCategoryCode field in the CDP event contains the category code(s) as a comma-separated string with no trailing separator (e.g. "IR1" for a single code, "IR1,BB" for multiple codes), consistent with the abandoned cart integration comma-separated format.
