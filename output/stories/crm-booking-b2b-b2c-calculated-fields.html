CR: Add B2B/B2C Boolean Indicator to Booking Event Integrations (INT-100, INT-025, INT-024.1)

Interfaces: INT-100, INT-025, INT-024.1 | Initiative: CRM Marketing Automation – Calculated Fields: Booking B2B or B2C | Status: Draft

Summary

Three existing MuleSoft booking event integrations — INT-100 (Booking Event Integration), INT-025 (Booking PAX Change Event Ingestion), and INT-024.1 (Booking Event Integration) — must be updated to pass through a new B2B/B2C boolean field sourced from DTS. The field is derived by DTS from the Booking Channel node in the booking event: true indicates a B2C booking; false indicates a B2B booking. MuleSoft will pass this field through to the CDP without applying any further transformation logic. This change enables the CRM Marketing team to segment customers by booking channel and deliver personalised post-booking communications.

Change Scope

  • Add data mapping for the new B2B/B2C boolean field (sourced from DTS) to the outbound CDP payload in INT-100.
  • Add data mapping for the new B2B/B2C boolean field (sourced from DTS) to the outbound CDP payload in INT-025.
  • Add data mapping for the new B2B/B2C boolean field (sourced from DTS) to the outbound CDP payload in INT-024.1.

Interfaces Affected

  • INT-100 — Booking Event Integration (DTS → MuleSoft → CDP)
    Add data mapping for B2B/B2C boolean field. No derivation logic in MuleSoft. Field passed as-is from DTS payload to CDP booking profile.
  • INT-025 — Booking PAX Change Event Ingestion (DTS → MuleSoft → CDP)
    Add data mapping for B2B/B2C boolean field to the booking PAX change event CDP payload. No derivation logic in MuleSoft.
  • INT-024.1 — Booking Event Integration (DTS → MuleSoft → CDP)
    Add data mapping for B2B/B2C boolean field. No derivation logic in MuleSoft. Field passed as-is from DTS payload to CDP booking profile.

Rationale

  • CRM and CDP teams require a B2B/B2C indicator on booking events to enable personalised post-booking marketing communications and audience segmentation based on booking channel.
  • The agent type is intentionally excluded from the B2B/B2C mapping as its cardinality is too complex to map directly to a binary classification.
  • All three interfaces must be updated to ensure a consistent and complete data payload reaches the CDP across all booking event types.

Acceptance Criteria

GIVEN a valid booking event is published by DTS to INT-100, INT-025, or INT-024.1 with the B2B/B2C boolean field set to true (B2C booking)
WHEN the respective integration processes the event
THEN the outbound CDP payload contains the B2B/B2C boolean field with value true, and the event is processed successfully.

GIVEN a valid booking event is published by DTS to INT-100, INT-025, or INT-024.1 with the B2B/B2C boolean field set to false (B2B booking)
WHEN the respective integration processes the event
THEN the outbound CDP payload contains the B2B/B2C boolean field with value false, and the event is processed successfully.

GIVEN a booking event is published by DTS to INT-100, INT-025, or INT-024.1 without the B2B/B2C boolean field present in the payload (field absent or null)
WHEN the respective integration processes the event
THEN the integration does not fail or raise a processing error; the CDP payload is forwarded successfully with the B2B/B2C field absent or null; and a warning or informational log entry is written indicating the field was not present.

GIVEN a booking event is published by DTS to INT-100, INT-025, or INT-024.1 with the B2B/B2C field containing a non-boolean value (e.g. a string or integer)
WHEN the respective integration processes the event
THEN the integration does not throw an unhandled exception; an error or warning is logged; the event is either forwarded with the field nulled out or routed to a dead-letter / error queue per the existing error handling policy; and no data loss occurs for other fields in the booking event payload.
