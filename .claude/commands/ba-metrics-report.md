Generate the weekly BA metrics report for the current week (Monday 00:00 to Friday 18:00 local time).

Read all metrics files in `output/metrics/`, filter to those created this week, and produce the report below.

---

## Step 1 — Collect this week's metrics

```bash
mkdir -p output/metrics/weekly_reports
python3 -c "
import json, glob, sys
from datetime import datetime, timedelta

files = sorted(glob.glob('output/metrics/*.json'))
now = datetime.now()
monday = now - timedelta(days=now.weekday())
monday = monday.replace(hour=0, minute=0, second=0, microsecond=0)
friday_cutoff = monday + timedelta(days=4, hours=18)

records = []
for f in files:
    with open(f) as fh:
        m = json.load(fh)
    ts = m.get('timestamp_created')
    if not ts:
        continue
    created = datetime.fromisoformat(ts.replace('Z', '+00:00')).replace(tzinfo=None)
    if monday <= created <= friday_cutoff:
        records.append(m)

print(json.dumps(records))
"
```

If no records are returned, print:
> "No features were processed this week. No report generated."
Then stop.

---

## Step 2 — Calculate metrics

For each feature in this week's records, calculate:
- **Iterations** = `phases.spec.iterations + phases.stories.iterations`
- **Template compliance** = `1 − (total_structural_fixes / total_fixes)` × 100 — where totals are summed across all amend runs; display as `X%` or `—` if no amend runs

Across all features, calculate:
- **Average iterations per feature** = mean of per-feature iterations
- **Template compliance rate** = mean of per-feature compliance values (exclude features with no amend runs)
- **Structural fix %** = total structural fixes / total fixes across all features × 100
- **Total time** = sum of `total_duration_minutes` / 60 → hours and minutes
- **Most common content issue** = most frequent rule number found in content violations (Rules 1,2,6,7) across all validation runs this week — label with the rule name (Rule 1 — TBC fields, Rule 2 — Vague ACs, Rule 6 — Missing owner, Rule 7 — Untested UCs)
- **Features needing attention** = features where spec.iterations + stories.iterations > 2

---

## Step 3 — Build the report

Compose the report in this exact format:

```
# Weekly BA Metrics Report

**Generated:** [DD/MMM/YYYY] at 5pm GMT+1
**Week:** [Mon DD MMM] – [Fri DD MMM YYYY]

---

## Features Processed This Week

| Feature | Req ID | Iterations | Template compliance | Duration | Status |
|---|---|---|---|---|---|
| [feature_slug] | [req_id or —] | [n] | [X% or —] | [n min] | [status] |

**Total features:** [n]

---

## Weekly Trends

- Average iterations per feature: [n]  (target: <1.5)
- Template compliance rate:       [X%]  (target: >90%)
- Structural fix rate:            [X%]  (target: <10%)
- Total BA time this week:        [n h n min]
- Most common content issue:      [Rule N — name] ([n] occurrences)

---

## Recommendations

- Features needing attention (>2 iterations): [list feature slugs, or "None"]
- Next steps: [one sentence derived from the most common issue — e.g. "Review acceptance criteria quality in story templates to reduce Rule 2 flags."]

---

*Generated by /ba-metrics-report*
```

---

## Step 4 — Save and print

Save the report to:
```bash
output/metrics/weekly_reports/weekly_report_[YYYY-MM-DD].md
```
where `[YYYY-MM-DD]` is today's date.

Then print the full report content to the terminal so it is visible when run on a schedule.

Tell the user (or log):
> "Weekly report saved to output/metrics/weekly_reports/weekly_report_[date].md"
